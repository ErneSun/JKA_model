## 2. Frozen scientific contract through Phase 2

Phase 1 and Phase 2 are mechanism-identification stages. Their primary route keeps the validated
V0.8 handoff frozen:

- encoder and decoder;
- JEPA online/target representation;
- V0.8 context encoder;
- nominal Koopman generator `A0`;
- cylinder-wake PDE, geometry, boundary conditions, and physical metrics.

Only the low-rank adaptive generator, condition observer, and Phase-2 mechanism heads are trained.
The route must not introduce an additive state residual or a persistent residual state `z_R`.
At initialization, all adaptive coordinate heads are zero, so

\[
A_t=A_0.
\]

The V0.8 strict-readiness field is still `NOT_READY`; therefore all current V0.9 formal results use
the `supported` handoff policy and have evidence tier `EXPLORATORY_CONDITIONAL`. They are valuable
mechanism evidence, but they do not make V1.0 ready.

Known-condition and latent-inferred routes have different meanings:

- `known_condition`: receives the true causal condition `q_t` as a privileged oracle control;
- `latent_inferred`: must infer the condition from causal model inputs and is teacher-free on the
  locked test split.

Failure of the observer must not invalidate the known-condition mechanism test. Conversely, a
known-condition success must not be reported as a deployable latent success.

## 3. The three-phase research questions

### Phase 1 — Constrained observable optimization

Can the frozen adaptive operator improve physically meaningful observables without violating
physical non-inferiority?

### Phase 2 — Identifiable static/dynamic adaptive Koopman

After the current operating condition is isolated, does older history contain a distinct and
predictive operator innovation?

### Phase 3 — Physical-manifold representation and matched route study

Is the remaining physical error imposed by the frozen representation, and can a physically
consistent representation remove it without destroying Koopman structure or confusing added
capacity with a mechanism improvement?

## 4. Phase 1 record

### 4.1 Problem addressed

The original V0.9 objective mixed forecast, rollout, force, divergence, and boundary terms with
very different scales. It also trained mostly at shorter horizons while evaluating H80. This made
it difficult to tell whether failures were caused by the representation, the operator, loss scale,
gradient conflict, or absent long-horizon exposure.

### 4.2 Main mathematical and software additions

1. **Four-level error attribution**

   The locked split evaluates

   \[
   U,\quad D(E(U)),\quad D(e^{A_0\Delta t}E(U)),\quad
   D(e^{A_t\Delta t}E(U)).
   \]

   This separates the numerical-data floor, representation floor, nominal dynamics error, and
   adaptive dynamics error.

2. **Train-only robust observable scaling**

   Each observable uses a fixed train-only MAD or centered RMS scale and standardized Huber loss.
   Force losses include causal waveform, correlation, and spectral information.

3. **Physics as inequality-constrained optimization**

   Divergence, boundary, and operator-burden requirements became augmented-Lagrangian constraints
   instead of arbitrary weighted penalties:

   \[
   \mathcal L_{AL}=\mathcal L_{primary}
   +\sum_k\lambda_k[g_k]_+
   +\frac{\rho_k}{2}[g_k]_+^2.
   \]

4. **H4-H80 stochastic curriculum**

   Training samples horizons from `{4, 8, 16, 32, 80}` with importance correction. The r1
   revision also added H80 to latent-rollout supervision and validation rank selection.

5. **Measured gradient geometry and delayed PCGrad**

   Forecast, structural, observable, and physical gradients are audited. PCGrad starts only after
   the physical ramp is fully active.

6. **r1 evidence-driven corrections**

   The first formal run exposed a zero-baseline representation gate, strong physical/rollout
   conflict, missing H80 latent supervision, cross-horizon constraint cancellation, and excessive
   dual growth. Phase-1 r1 corrected each issue without changing the frozen representation.

## 5. Phase 2 base implementation

### 5.1 Mathematical factorization

Phase 2 replaced the confounded context-to-operator map with

\[
A_t=A_0+\Delta A_s(q_t)+\Delta A_d(h_t,q_t),
\]

\[
\Delta A_s=\sum_{j=1}^{r_s}\phi_j(q_t)u_j^s(v_j^s)^T,
\qquad
\Delta A_d=\sum_{k=1}^{r_d}\xi_{t,k}u_k^d(v_k^d)^T.
\]

Here `Delta A_s` represents the operator change explained by current operating condition, while
`Delta A_d` is intended to represent genuine history-dependent innovation. Identifiability uses

\[
\mathbb E[\xi_t\mid q_t]\approx0,
\qquad
\langle u_j^s(v_j^s)^T,u_k^d(v_k^d)^T\rangle_F\approx0.
\]

There is deliberately no variance floor on `xi`: a zero dynamic innovation is a valid result when
the data do not support memory dependence.

### 5.2 Controls and data design

The same cylinder PDE and geometry were retained, but the variable-condition schedule family was
expanded to include upward, downward, fast, slow, abrupt, cyclic, and different-dwell transitions.
Locked evaluation compares:

1. nominal `A0`;
2. global/static mean correction;
3. condition-only operator;
4. condition plus dynamic innovation;
5. shuffled-history dynamic control;
6. known and latent-inferred condition modes;
7. matched-present pairs with similar current condition/state but different older histories.

### 5.3 First Phase-2 result

`v09-added-p2-identifiable-20260823T100133Z` completed all 8 rank-sweep runs and 5 formal
train/evaluation pairs. It then failed at seed 47, latent mode, operator seed 907 with non-finite
context input during closed-loop validation. This was an incomplete workflow, not a negative
scientific result.

The failure showed that condition-rate extrapolation, observer/operator gradient coupling, and an
unbounded adaptive symmetric generator component could amplify a latent closed loop before the
next frozen context call.

## 6. Phase 2 stability correction

### 6.1 Modifications

The first correction was problem-independent:

- smoothly bound normalized observer outputs;
- train the observer with Huber loss;
- stop the operator gradient through latent `q_hat`;
- project the symmetric low-rank increment into a logarithmic-norm trust region;
- reject non-finite loss/gradient values at the originating epoch and rollout step.

The initial trust region bounded each branch separately. This preserved dyadic rank and prevented
the adaptive generator from injecting uncontrolled instantaneous growth.

### 6.2 Formal result

`v09-added-p2-stable-20260823T110904Z` completed all `18/18` formal train/evaluation pairs, and all
`216/216` rollouts were finite. It selected rank 2.

However, this solution was too conservative:

- physical non-inferiority passed `12/18` runs;
- long-rollout gate passed `0/18`;
- observer passed `0/18`;
- operator burden collapsed to approximately `0.55%-0.67%`;
- mean known-condition one-step gain was approximately `0.64%`;
- mean latent-inferred one-step gain was approximately `0.02%`;
- known dynamic-over-static gain was approximately `0.21%`;
- latent dynamic-over-static gain was approximately `0.05%`.

The result was numerically safer but scientifically `NOT_SUPPORTED`. It demonstrated over-
constraint rather than numerical divergence.

## 7. Phase 2 Fix 1 — continuous mechanism curriculum

### 7.1 Why Fix 1 was needed

The stability correction attempted to learn condition dependence, history innovation, and the
observer simultaneously under tight branch-wise budgets. The easiest solution was to keep the
adaptive operator nearly zero. Fix 1 therefore made the causal order of identification explicit.

### 7.2 Modifications

One continuous formal run was divided into auditable stages:

1. `static_oracle`: learn `Delta A_s(q)` from true training/validation conditions;
2. `dynamic_residual_oracle`: restore the selected static state, detach the static branch, and fit
   `Delta A_d` to the remaining forecast error;
3. `observer_calibration`: train the condition observer separately; latent joint refinement can
   begin only after validation observer gates pass.

Additional changes were:

- project the **combined** increment `Delta A_s + Delta A_d`, not two half-budget branches;
- increase the total stability budget continuously `0.05 -> 0.10 -> 0.15`;
- expose H80 earlier and more strongly in the dynamic stage;
- use known-condition oracle rank selection so observer weakness cannot choose rank;
- prioritize H80 gain among burden-feasible ranks;
- report numerical stability separately from long-rollout predictive skill.

### 7.3 Formal result

`v09-added-p2-continuous-20260823T133237Z` completed correctly:

- `18/18` formal train/evaluation pairs completed;
- `216/216` rollouts were finite;
- numerical stability passed `18/18`;
- selected rank: 8;
- mean known-condition H80 gain: `2.085%`;
- mean known operator-explained fraction: `5.541%`;
- mean latent H80 gain: `1.080%`;
- known H80 per-run pass: `6/9`;
- latent H80 per-run pass: `0/9`;
- physical non-inferiority: `7/18`;
- all-horizon rollout skill: `0/18`;
- observer readiness: `0/18`;
- known dynamic-over-static mean gain: `0.540%`;
- latent dynamic-over-static mean gain: `0.103%`.

The horizon means were imbalanced: known gains at H8, H16, and H32 were approximately `0.751%`,
`0.876%`, and `0.175%`, while H80 was stronger. The H80 effect was also seed-sensitive:

- seed 47: approximately `-0.245%`;
- seed 53: approximately `+2.357%`;
- seed 59: approximately `+4.143%`.

The observer remained far below readiness, with latent NRMSE around `0.966` against a `<=0.5`
gate and minimum R2 around `-0.021` against a `>=0.2` gate. The dynamic branch did not beat the
condition-only branch by the declared 2% margin.

### 7.4 Fix-1 conclusion

Fix 1 recovered a real known-condition long-horizon signal and proved that the stability fix had
been suppressing useful operator motion. It did **not** establish robust Phase-2 support:

- the gain was concentrated at H80 instead of all horizons;
- it was not stable across seeds;
- the selected rank 8 had a positive validation boundary constraint;
- physics deteriorated to `7/18`;
- the observer could not infer the condition;
- the dynamic history branch did not add material information beyond current condition.

The formal scientific result remained `NOT_SUPPORTED` and V1.0 remained `NOT_READY`.

## 8. Phase 2 Fix 2 — current unvalidated implementation

### 8.1 Status boundary

**This is the current code state.** Phase 2 Fix 2 is implemented in the working tree and has passed
49 targeted V0.9 software tests, Ruff, and `git diff --check`. No formal GPU session has yet tested
its scientific effect. Every effect in this section is therefore an intended effect or an
acceptance question, not a result.

### 8.2 Fix 2A — physics-first rank and checkpoint selection

Fix 1 could select rank 8 because H80 gain outranked a positive boundary violation. Fix 2 changes
both rank and checkpoint selection to the lexicographic contract

\[
\boxed{
\text{physical feasibility}
\prec\text{burden feasibility}
\prec\text{H80 gain}
\prec\text{validation objective}
\prec\text{smaller rank}
}.
\]

Implementation details:

- boundary and divergence feasibility must both be nonpositive;
- validation uses the worst batch/horizon constraint and burden maxima, not averages;
- if no rank is physically feasible, first minimize the maximum positive physical violation, then
  compare burden and gain;
- an immature checkpoint captured before the physics ramp reaches 1 cannot outrank a mature one;
- each new mechanism stage restores the previous stage's selected checkpoint;
- optimizer moments are reset at stage transitions so they do not carry a stale search direction.

Expected effect: prevent predictive gain from purchasing an invalid boundary solution and prevent
stage transitions from inheriting an arbitrary final SGD iterate.

Risk: a strict physics-first selector may return a lower-gain model. That is intentional. If all
ranks violate physics, the report must expose the smallest violation rather than call the model
supported.

### 8.3 Fix 2B — known-oracle and latent-observer gate separation

The known-condition route now tests only whether the operator can use a known physical condition.
It no longer fails merely because the latent observer is weak. The latent route and overall
deployable claim still require the observer gate.

Expected effect: distinguish

1. operator/mechanism capacity with true `q_t`; and
2. deployability when `q_t` must be inferred.

This cannot improve the latent model by itself. It improves the validity of the scientific
diagnosis and prevents an observer failure from erasing a genuine oracle mechanism signal.

### 8.4 Fix 2C — causal condition observer

The observer input is expanded from frozen context alone to

\[
o_t=\left[
z_t,
\frac1H\sum_{j=0}^{H-1}z_{t-j},
\frac{z_t-z_{t-H+1}}
{\sum_{j=1}^{H-1}\Delta t_{t-j}}
\right],
\qquad
\hat q_t=Q(c_t,o_t).
\]

It sees the current latent state, a causal history mean, and a finite-time trend. It is supervised
during the static- and dynamic-oracle stages as well as its dedicated calibration stage, but its
prediction is not consumed by either oracle operator branch. Thus observer gradients cannot alter
the oracle condition or contaminate operator identification. Locked latent evaluation remains
teacher-free and receives no condition label.

Expected effect: make condition and condition rate observable from explicit causal motion rather
than asking one frozen summary vector to contain everything.

Risk: the frozen latent trajectory may still not identify `q_t`; the correct result would remain
`LATENT_CONDITION_NOT_IDENTIFIABLE`.

### 8.5 Fix 2D — conditional residualization of history

The dynamic branch previously had enough access to condition-correlated context to duplicate the
static branch. Fix 2 introduces a learned conditional context predictor:

\[
\hat h(q_t)=M_\theta(q_t),
\qquad
h_t^\perp=h_t-\hat h(q_t),
\qquad
\xi_t=H_\psi(h_t^\perp).
\]

The dynamic coordinate head and dynamic trust gate receive only `h_perp`; they do not receive `q`
directly. `M_theta` is trained with a smooth conditional-context reconstruction loss with weight
`lambda_context_residualization = 0.10`. The existing kernel conditional-centering penalty still
enforces `E[xi|q] approximately 0`, and static/dynamic dyadic bases remain orthogonal. No dynamic
variance floor is added.

Expected effect: force `Delta A_s` to explain current-condition dependence and reserve
`Delta A_d` for information in history that cannot be predicted from the current condition.

Risk: if history contains no additional predictive information, residualization should drive the
dynamic branch toward zero. That is a valid negative mechanism result, not an implementation
failure.

### 8.6 Fix 2E — relative-to-nominal multi-horizon objective

Every optimized horizon now uses

\[
\mathcal L_h=
\frac{
\operatorname{MSE}(z_{t+h}^{adapt},z_{t+h}^{true})
}{
\operatorname{stopgrad}
\left[\operatorname{MSE}(z_{t+h}^{nom},z_{t+h}^{true})\right]+\epsilon
}.
\]

The configured rollout weights are `[0.5, 0.6, 0.8, 1.0, 1.0]`. The denominator is frozen with
respect to optimization, so the model cannot improve the ratio by changing the nominal baseline.

Expected effect: align training with the declared relative-gain gates and stop H80 from dominating
only because its absolute MSE is larger. H8-H32 should receive meaningful pressure while H80
remains important.

Risk: a near-zero nominal error could amplify a horizon, so the epsilon and finite checks remain
part of the numerical contract.

## 9. Phase 3 implementation plan

### 9.1 Entry condition

Phase 3 is the first stage allowed to modify the representation. It must begin only after the Phase
2 Fix 2 formal report is reviewed. The Fix 2 outcome determines whether Phase 3 targets a physical
representation floor, condition observability, or both.

Phase 3 must not silently replace the frozen route. The frozen Phase-2 model remains the primary
mechanism-identification reference.

### 9.2 Physical-manifold question

For incompressible cylinder flow, define schematically

\[
\mathcal M_{phys}=\{U:\nabla\cdot u=0,\;B(U)=0\},
\]

where `B` includes inlet, wall/cylinder no-slip, and outlet contracts. The current decoder may map
a latent state outside this manifold even when latent dynamics are stable. Phase 3 asks whether
enforcing or learning this manifold can reduce the reconstruction/rollout physical floor without
destroying the useful near-linear Koopman evolution.

### 9.3 Candidate representation mechanisms

Implement candidates behind a common, configurable physical-decoder interface. Do not combine all
candidates in the primary experiment.

1. **Geometry-aware differentiable Helmholtz-Hodge projection**

   \[
   \tilde u=D_u(z),\qquad
   u=\tilde u-\nabla\phi,\qquad
   \nabla^2\phi=\nabla\cdot\tilde u.
   \]

   The Poisson solve and lifting must honor the actual cylinder/inlet/wall/outlet conditions. A
   periodic FFT projection is not valid for this geometry.

2. **Stream-function decoder for two-dimensional incompressibility**

   \[
   u=\partial_y\psi,\qquad v=-\partial_x\psi.
   \]

   Boundary lifting supplies prescribed inlet and no-slip values. Pressure remains a separate
   decoded field.

3. **Latent/physical round-trip consistency**

   Any physical projection must remain visible to the latent model:

   \[
   E(\Pi_{phys}(D(z)))\approx z.
   \]

   A post-hoc correction used only for visualization is not an acceptable primary solution.

4. **Optional tangent-consistency diagnostic before training**

   For constraint map `g(U)=0`, measure whether the decoded latent vector field is tangent:

   \[
   J_g(D(z))J_D(z)\,\dot z\approx0.
   \]

   This diagnostic can determine whether failure is decoder-owned or caused by latent dynamics.
   Projection of the vector field itself should be added only if the diagnostic and reconstruction
   tests justify it.

### 9.4 Matched route comparison

Phase 3 must implement and report three explicitly named routes:

#### `frozen` — primary mechanism route

- keep the V0.8 encoder, decoder, JEPA representation, context, and `A0` frozen;
- train only the Phase-2 Fix 2 adaptive components;
- preserve it as the causal reference for whether operator adaptation alone is sufficient.

#### `joint` — scoped physical representation adaptation

- initialize from the same V0.8 handoff;
- train the physical decoder/projection, a tightly scoped encoder tail or latent-alignment layer,
  observer, and adaptive operator;
- use lower representation learning rates;
- log `A0`, representation, and latent-geometry drift;
- retain JEPA/round-trip consistency so physical correction does not destroy predictive structure.

#### `from_scratch` — capacity and route-compatibility control

- initialize representation, context, and operator from scratch on the same variable-condition
  data;
- do not describe it as inherited continuation of V0.8;
- use it to test whether the V0.8 representation path itself limits the problem.

All three routes must match:

- train/validation/locked-test trajectories;
- backbone/data seeds and operator initializations;
- condition modes and Phase-2 controls;
- epochs, early stopping, and horizon exposure;
- parameter count or compute budget, with both reported;
- observable scaling and physical gates;
- final checkpoint-selection contract;
- evaluation code and report schema.

### 9.5 Recommended Phase-3 order

#### Phase 3.0 — ingest Phase 2 Fix 2 evidence

- review rank sweep, selected checkpoint, constraint maxima, observer metrics, horizon gains,
  paired histories, and seed dispersion;
- classify the dominant bottleneck before changing representation;
- freeze the Fix 2 result and configuration as the comparison baseline.

#### Phase 3.1 — representation-floor and tangent audit

- evaluate numerical/reconstruction/nominal/adaptive physical errors;
- add geometry-aware divergence and boundary diagnostics at reconstruction level;
- measure round-trip latent drift and optional tangent residual;
- run no expensive full retraining yet.

#### Phase 3.2 — physical decoder interface and unit tests

- implement one primary projection/decoder candidate modularly;
- verify differentiability, boundary handling, divergence behavior, device/dtype support, and exact
  checkpoint/config provenance;
- verify that disabling the module reproduces the frozen route.

#### Phase 3.3 — matched `joint` route

- start from the identical V0.8 checkpoint;
- use a scoped trainable parameter allow-list;
- monitor representation and `A0` drift;
- stop if physical improvement is obtained only by unacceptable forecast/JEPA degradation.

#### Phase 3.4 — matched `from_scratch` control

- match data, seeds, epochs, evaluation, and reported compute;
- do not reuse inherited-readiness claims;
- interpret a win as route incompatibility/capacity evidence, not automatic V1.0 success.

#### Phase 3.5 — nested aggregation and decision

- aggregate all seeds/initializations/condition modes;
- compare frozen, joint, and from-scratch under identical gates;
- produce one compact report and preserve all raw artifacts under the resolved run ID.

### 9.6 Phase-3 acceptance

Phase 3 is scientifically supported only when:

1. reconstruction-level divergence and boundary gates pass;
2. all physical rollout gates, including H80, pass without relaxed thresholds;
3. latent and decoded long rollouts remain finite and burden-bounded;
4. Phase-2 condition/history conclusions remain valid under the selected representation route;
5. `joint` improvement over `frozen` is nested-seed robust and not explained only by parameter or
   compute count;
6. locked latent evaluation remains teacher-free;
7. all required artifacts exist for 3 backbone seeds x 3 operator initializations x both condition
   modes;
8. V1.0 is declared ready only if the inherited strict V0.8 handoff and all 3/3 final V0.9
   backbone seeds pass.

Interpretation rules:

- `frozen` wins: retain the simpler frozen mechanism route;
- `joint` wins: adopt scoped physical representation adaptation;
- only `from_scratch` wins: report incompatibility with the inherited representation chain;
- none pass: do not add an arbitrary residual closure; reassess data identifiability, operator
  class, or problem family first.
